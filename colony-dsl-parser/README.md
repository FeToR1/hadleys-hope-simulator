# Colony DSL: ANTLR4 + Kotlin

Этот проект содержит синтаксическую часть языка Colony для репозитория
`hadleys-hope-simulator`, ветки `prototype/dsl-vm`.

Основная ответственность проекта — разработка фронтенда компилятора на
**ANTLR4 + Kotlin**:

- описание грамматики языка в ANTLR4;
- лексический и синтаксический анализ исходного `.colony`-кода;
- построение собственного AST на Kotlin;
- сохранение координат исходного текста для узлов AST;
- сбор и форматирование синтаксических ошибок;
- подготовка структуры, которую следующие этапы компилятора смогут использовать
  для дальнейшей обработки и генерации байт-кода.

## Граница проекта

В этом проекте реализуется только синтаксический фронтенд.

После построения AST следующий этап компилятора получает уже не ANTLR parse tree,
а собственные Kotlin-объекты `colony.ast.*`.

В текущую часть работы не входят:

- проверка типов и совместимости значений;
- разрешение имён и областей видимости;
- проверка единиц измерения;
- проверка допустимых операций конкретной сущности;
- проверка эффектов или других правил выполнения программы;
- реализация виртуальной машины;
- интерпретация байт-кода;
- физическая модель мира и World Kernel.

ANTLR parser contexts намеренно не используются как долговременная модель
компилятора: `AstBuilder` преобразует их в Kotlin AST с координатами исходного
текста.

## Конвейер данного проекта

```text
.colony
  -> ANTLR4 lexer/parser
  -> parse tree
  -> AstBuilder
  -> Kotlin AST + SourceSpan
  -> следующий этап компилятора
```

Целевая виртуальная машина проекта в дальнейшем будет простой стековой машиной.
Это учитывается как внешнее ограничение будущего компилятора, но реализация VM
в данный проект не входит.

## Важное решение по реализации

Грамматика генерируется для Java target ANTLR и используется из Kotlin/JVM.
ANTLR 4.13.2 предоставляет официальный Java target; его использование позволяет
не добавлять в компилятор дополнительный нестандартный target генерации кода.
Kotlin может напрямую использовать сгенерированные Java-парсер и runtime.

## Генерируемые исходные файлы

Из `src/main/antlr/Colony.g4` необходимо сгенерировать `ColonyLexer`/
`ColonyParser`, а также классы visitor в каталог сгенерированных исходников
сборки.

Типовая настройка Gradle:

```kotlin
plugins {
    kotlin("jvm") version "<версия Kotlin>"
    antlr
}

dependencies {
    antlr("org.antlr:antlr4:4.13.2")
    implementation("org.antlr:antlr4-runtime:4.13.2")
}
```

Точную версию Kotlin-плагина следует брать из существующей сборки компилятора
команды, а не фиксировать в этом модуле.

## Синтаксис, покрываемый MVP

- `event Name { field: Type; }`;
- `behavior Name for Kind { ... }`;
- `enum`;
- `param` и инициализированный `state`;
- `on Event(message) as rule { ... }`;
- `every 1s as rule { ... }`;
- `let`, `if`, `else`, `if let`;
- присваивания и выражения-операторы;
- `send Event { ... } to target;`;
- вызовы через поля, например `power.request(2kW)`;
- `chance(p, "site")`, `hazard(rate, "site")`;
- обобщённые типы, например `Ref<Heater>`, `Option<Bool>`, `List<T>`;
- числовые литералы с суффиксами единиц, например `18degC`, `2kW`, `5mps`, `20hp`, `1s`;
- логические, числовые, строковые литералы и литерал `none`.

Грамматика не включает `while`, рекурсию, динамическое создание сущностей,
сетевой/файловый ввод-вывод и прямой доступ к системному времени, поскольку
эти возможности находятся за пределами текущего MVP.

## Обозначение сущностей в языке

Исходная программа описывает поведение сущности конструкцией:

```colony
behavior KettleControl for Kettle {
    ...
}
```

`Kettle`, `Heater`, `House`, `Rover`, `Human`, `Marine`, `Computer`,
`HeatingNode`, `WaterNode`, `InternetNode`, `GarbageTruck`, `AtomicReactor`,
`Xenomorph` и другие подобные названия используются в исходном коде как имена
типов/сущностей.

Грамматика специально не содержит отдельного набора правил для каждой сущности:
после `for` используется обычное имя типа. Благодаря этому добавление нового
названия сущности не требует изменения ANTLR-грамматики.

## AST

AST находится в `src/main/kotlin/colony/ast/Ast.kt` и содержит отдельные узлы для:

- программы и объявлений;
- `event` и `behavior`;
- `enum`, `param`, `state`;
- обработчиков `on` и `every`;
- блоков и операторов;
- `let`, `if`, `else`, `if let`;
- присваиваний и `send`;
- литералов;
- унарных и бинарных выражений;
- обращения к членам, вызовов и индексирования;
- записей и инициализаторов полей;
- ссылок на типы;
- числовых значений с единицами.

Каждый узел AST содержит `SourceSpan` с начальной и конечной строкой, столбцом
и смещением в исходном тексте.

## Диагностика синтаксических ошибок

`ColonyParserFacade` объединяет ошибки лексера и парсера.

Каждая диагностика содержит:

```text
строка
столбец
сообщение
фрагмент исходного текста, если доступен
```

Пример:

```text
7:13: mismatched input 'every' expecting ';' near 'every'
```

Для консольного режима дополнительно существует
`FirstErrorThrowingListener`, который прекращает разбор после первой ошибки.

## Примеры

Каталог `examples/` содержит корректные примеры конструкций языка для разных
типов сущностей: отопительного узла, жителя, ксеноморфа, инфраструктуры и
нескольких других объектов симулятора.

Каталог `tests/` разделён на два набора:

- `tests/valid/` — корректные программы, проверяющие разные конструкции языка;
- `tests/invalid/` — синтаксически некорректные программы для проверки диагностики.

## Структура проекта

```text
src/main/antlr/Colony.g4
    грамматика ANTLR4

src/main/kotlin/colony/ast/
    собственный AST и координаты исходного текста

src/main/kotlin/colony/parser/
    построение AST и диагностика синтаксических ошибок

docs/
    описание синтаксического контракта языка

examples/
    примеры корректных программ на Colony

tests/valid/
    корректные программы для проверки парсера

tests/invalid/
    синтаксически некорректные программы
```

## Что не входит в эту часть работы

Этот репозиторий не реализует виртуальную машину и не содержит её C/C++
интерпретатор.

Также здесь не реализуются последующие этапы обработки AST. Граница данного
проекта заканчивается на получении корректного Kotlin AST с координатами
исходного текста и диагностикой синтаксических ошибок.
