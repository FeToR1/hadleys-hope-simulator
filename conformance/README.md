# Эталонные векторы для стековой ВМ

Наборы данных, по которым любая реализация ВМ проверяется на совпадение с эталоном: те же программы, те же кадры,
те же результаты. Векторы порождает эталонная ВМ на Kotlin; вторая, независимая реализация на Python
(`run_vectors.py`) написана только по описанию артефакта и воспроизводит все проверки.

| Файл | Что проверяет |
|---|---|
| `heater.json` | Дом и обогреватель: события между программами, гистерезис, порядок доставки |
| `resident.json` | Житель: вероятностный вандализм при трёх зёрнах, `Duration`, `Option`, `nearest`, `clamp` |
| `xenomorph.json` | Ксеноморф: `hazard`, движение, выбор цели, два зерна |
| `kettle.json` | Чайник: пороги температуры и условия отказа |
| `language.json` | Возможности языка: числа, короткое замыкание, ветвления, события, таймеры, время, откат при ошибке |
| `prng.json` | Генератор случайных чисел: 180 векторов, включая нелатинские ключи, отрицательное зерно, счётчик 2^40 |

Исходные тексты программ: `colony-dsl-parser/examples/*.colony`, `examples/integration/devices.colony`,
`programs/language.colony`.

## Формат файла программы

```text
{ "conformance": 1, "contract": 2, "name", "source", "program": <артефакт v1>,
  "cases": [ { "name", "behavior", "entityId", "seed", "params", "initialState",
               "steps": [ { "tick", "view", "events": [ {eventId, sender, sequence, fields} ],
                            "expect": { "failure"?, "intents": [ {operation, arguments} ],
                                        "events": [ {target, eventId, sequence, fields} ], "state" } } ] } ] }
```

Каждый случай — одна ВМ: она создаётся с `entityId`, `behavior`, `params` и `seed`, состояние после инициализаторов
должно совпасть с `initialState`, затем по очереди подаются шаги.

## Правила сравнения

- Числа сравниваются по значению: `2` и `2.0` совпадают. Строки, булевы значения и `null` — точно.
- Порядок ключей объекта не важен; порядок элементов списков важен (намерения и исходящие события идут в порядке исполнения).
- `failure: true` означает, что шаг обязан завершиться ошибкой и оставить состояние, счётчики случайных чисел и номер
  исходящего события такими, какими они были до шага. Текст ошибки не сравнивается.
- Входящие события ВМ упорядочивает сама по `(sender, sequence)`; в векторах они нарочно поданы вразнобой.

## Случайные числа

Описание алгоритма лежит в `prng.json`. Каждая запись содержит хешируемые байты, первые восемь байтов SHA-256,
53 старших бита, результат и его точный битовый образ. Для проверки хватает `hashlib` и `struct`:
`python run_vectors.py` делает это для всех 180 записей.

## Запуск и обновление

```text
python conformance/run_vectors.py              # вторая реализация против векторов
colony-dsl-parser conformance conformance      # пересоздать векторы (из корня репозитория)
```

Тест `ConformanceVectorsTest` падает, если закоммиченные файлы устарели, и проверяет, что эталонная ВМ их воспроизводит.
Изменение семантики ВМ или набора команд — это новые векторы в том же коммите.
