# Идея: DSL → байт-код → ВМ

DSL описывает объекты через характеристики и поведение. Готовые конструкции: `entity`, `house`, `device`. ООП и наследование пока не нужны.

`entity Human { health = 100 } 60` объявляет шаблон и создаёт 60 экземпляров при запуске. Без количества — только шаблон. Вложенные объявления с количеством создают объекты для каждого экземпляра родителя.

## Пример синтаксиса

```text
world { steps = 5 dt = 60 }

house Cabin {
    temperature = 17

    device Heater {
        power = 3000
        enabled = false
    } 1

    behavior {
        if (temperature < 18) {
            Heater.enabled = true
        } else {
            Heater.enabled = false
        }
    }
} 1
```

Запуск файла автоматически создаёт мир и выполняет конечный прогон. Здесь — пять шагов по 60 модельных секунд. Пользователь не пишет `spawn()` или `simulation.run()`.

## Как это работает

- **ANTLR4 → компилятор на Kotlin → байт-код → ВМ на C/C++.** Обход дерева генерирует описания шаблонов и инструкции. Компилятор добавляет создание мира и цикл прогона; симуляция выполняется в ВМ.
- **Смешанный байт-код:** обычные инструкции для выражений, условий и изменения состояния плюс комплексные предметные инструкции. Например, условная `HEAT_STEP house, dt` целиком рассчитывает нагрев и теплопотери дома, а `CREATE template, count` создаёт экземпляры вместе с вложенными объектами. Каждая такая предметная инструкция вызывает алгоритм на C/C++ внутри ВМ; раскладывать его на элементарные инструкции байт-кода не требуется.
- **Шаг ВМ:** выполнить пользовательское поведение, рассчитать события и изменения состояния, продвинуть модельное время. Для постоянной интенсивности события `λ` в секунду вероятность за шаг `Δt`: `p = 1 − exp(−λΔt)`.

## Пример генерации байт-кода

Псевдокод обхода программы компилятором. Настройки содержат длительность шага и предел прогона:

```kotlin
fun visitProgram(node: ProgramNode) {
    emit(CREATE_WORLD, node.settings)

    for (declaration in node.declarations) {
        visit(declaration) // описания шаблонов и инструкции создания экземпляров
    }

    val dt = node.settings.dt
    val loop = markLabel()

    emit(RUN_BEHAVIORS)
    emit(UPDATE_HEAT, dt)
    emit(SAMPLE_FAILURES, dt)
    // emit(UPDATE_COSTS, dt) — будущее расширение
    emit(ADVANCE_TIME, dt)
    emit(JUMP_IF_NOT_FINISHED, loop)
    emit(HALT)
}
```

`emit` только записывает инструкции. Например, `UPDATE_HEAT 60` при исполнении вызывает C/C++-функцию ВМ, которая учитывает работающие отопители, рассчитывает нагрев и теплопотери за 60 секунд и обновляет температуры домов. В байт-коде это одна инструкция; весь алгоритм находится внутри её обработчика.

Будущий прототип: дом, отопитель и условие включения по температуре. Он должен показать DSL, листинг байт-кода и температуру на нескольких шагах. Экономика, сети, жители и аварии остаются точками расширения.
