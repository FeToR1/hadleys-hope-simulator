Задача: Разработать фронтенд-модуль «Интерактивная 2D-карта поселения и Топология сетей» для системы мониторинга симуляции LV-426.
Окружение и Технологический стек:

* Среда исполнения: Node.js v24.14.0 (учитывай синтаксис и особенности данной версии при написании скриптов сборки, если они потребуются).
* Язык: TypeScript с жесткой типизацией.
* Интерфейс и панели (UI): React (используется как декларативная обвязка для табов, боковых панелей управления и вывода текстовых метрик/логов).
* Графическое ядро карты: PixiJS v8 + плагин масштабирования/перетаскивания (например, @pixi/viewport или аналогичный контейнер, совместимый с v8) для отрисовки сетки поселения и агентов на GPU.
* Визуализация графов и инфраструктуры: AntV G6 (используется для построения интерактивных схем электросетей, водоснабжения и логических KPN-связей брокера).

Контекст проекта и ограничения производительности:

   1. Масштаб: Симуляция шахтерского поселка состоит из ~300 домов. Физика и логика распределены: у каждого дома, каждого прибора (обогреватель, чайник), а также жителей (300+ человек) и ксеноморфов есть собственная стековая ВМ, запущенная в отдельном процессе ОС. Суммарно на фронтенд одновременно транслируется состояние около 1300+ активных сущностей.
   2. Транспорт данных: Данные приходят от центрального Координатора (World Kernel) через WebSockets/SSE пакетами (батчами) раз в 100–500 мс.
   3. Оптимизация: Обновление объектов в PixiJS v8 и AntV G6 должно происходить по ссылке (мутацией свойств существующих инстансов), без полного пересоздания объектов сцены на каждом тике. Это необходимо, чтобы избежать утечек памяти и микрофризов интерфейса при обработке частых батчей данных. React должен управлять только внешними панелями (Sidebar) и не должен ререндерить графическую сцену.

Интерфейсы данных (Входной контракт):

interface EntityState {
  id: string;
  pid: number;
  type: 'house' | 'heater' | 'kettle' | 'civilian' | 'xenomorph' | 'power_node';
  status: 'nominal' | 'warning' | 'critical' | 'dead';
  metrics: {
    temperature?: number;
    power_consumption?: number;
    water_level?: number;
    stress?: number;
  };
  connectedTo: string[]; // ID смежных узлов для графа сетей AntV G6
  coordinates: { x: number; y: number };
}
interface TickBatch {
  tickId: number;
  timestamp: number;
  entities: EntityState[];
}

Что необходимо сгенерировать (Ожидаемый результат):

   1. State Manager (Менеджер состояния на TS): Класс/хук, который эффективно принимает TickBatch, обновляет внутренний индекс (Map<string, EntityState>) без выделения лишней памяти в куче (GC-free подход) и триггерит обновление в PixiJS и AntV G6.
   2. React + PixiJS v8 Viewport Component: React-компонент, который внутри себя инициализирует окно PIXI.Application (v8) и Viewport. Внутри должен быть реализован метод updateStage(entities: EntityState[]), меняющий координаты агентов и свойства (color, alpha) объектов-домов на лету. Реализуй интерактивность (eventMode = 'static') для кликов по домам.
   3. AntV G6 Network Topology Component: Компонент для отрисовки инфраструктурных сетей. Покажи, как эффективно передавать дельту изменений в граф G6 и динамически менять стили ребер (edges) и узлов при возникновении «каскада аварий» (например, делать связи тусклыми/красными, если источник питания dead).
   4. React UI Sidebar: Боковая панель на React, которая активируется при клике на дом в PixiJS или узел в AntV G6. Она должна выводить: PID процесса, список приборов внутри дома (ВМ обогревателя, чайника), их текущие метрики и виртуализированный список логов (чтобы вкладка не падала от тысяч строк).

Пиши чистый, строго типизированный код, готовый к интеграции. Сделай упор на правильную стыковку жизненного цикла React-компонентов с императивными движками PixiJS v8 и AntV G6.

ВАЖНО: Так как бэкенд и брокер еще не реализованы, напиши внутри React-приложения автономный Mock Data Generator. При старте он должен генерировать статическую сетку из 300 домов (с фейковыми PID) и связывать их в графы для AntV G6. Затем по таймеру setInterval (каждые 200–500 мс) генератор должен имитировать шаги симуляции: плавно двигать координаты агентов (жителей и ксеноморфов), случайно менять температуры в домах и раз в несколько секунд запускать цепочку аварии (отключение узла питания -> падение температуры дома -> прорыв труб), чтобы мы могли полностью протестировать интерфейс headless.
