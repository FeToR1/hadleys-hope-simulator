## Формат документа

Сразу после H1 — шапка одной строкой:

```markdown
> **Статус:** … · **Аудитория:** … · **Обновлять при:** … · **Источник истины:** …
```

Статусы: **актуально** (отражает текущее состояние), **спека** (документ-спецификация: описывает правила;
нереализованные части помечены в тексте — полностью реализованная спека является нормой), **историческое**
(не обновляется никогда). ADR используют собственное поле «Статус» внутри документа (принято/заменён/отменён)
вместо шапки. Для ссылок из кода и внешних ссылок в спеках сохранены якоря совместимости:
`#language` (colony-language), `#runtime`, `#world`, `#prng` (runtime-tick), `#contract` (http-api), `#vectors` (architecture).

## Антидублирующие правила

1. Термин определяется один раз — в глоссарии; в текстах — ссылка или уже определённое употребление.
2. Точные типы кадров и эндпоинты не переписываются из `types.ts`/`ObserverGateway.kt` в прозу —
   http-api.md фиксирует семантику и даёт ссылки.
3. Диаграмма живёт в одном файле (реестр ниже); в других местах — только ссылки.
4. «Почему» — только в ADR, «как» — в спеках, «что изменилось» — только в CHANGELOG.
5. Статус документа — только в его шапке; карты и списки статусы не повторяют.
6. Команды запуска: полная справка — AGENTS.md; README — быстрый старт и рецептурные команды запуска/замеров (подмножество справки); architecture.md команд не содержит.

## Процесс изменения документации

1. Код и затронутые документы — один коммит; видимое изменение — запись в [CHANGELOG](../../CHANGELOG.md).
2. Архитектурное решение — сначала [ADR](../adr/README.md), потом код и правки спек.
3. Переименование/перемещение документов — `git mv` (история важнее чистоты).
4. Для LLM-агентов: правила работы — в [AGENTS.md](../../AGENTS.md); этот файл агент читает,
   только когда меняет саму систему документации.
5. Перед коммитом documentation-изменений прогоняй `python docs/contribution/check-links.py` из корня
   репозитория — проверка относительных ссылок и якорей во всей markdown-документации.
