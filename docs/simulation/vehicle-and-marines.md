# Вездеходы и морские пехотинцы

## Общая модель

В симуляции `Rover` уже является программируемой сущностью. Для транспортной
механики он используется как общий транспорт: вездеход может доставлять людей
или группу морских пехотинцев, а после выполнения перевозки возвращается к своим
обычным задачам ремонта.

В полном сценарии четыре машины работают по этой общей программе `RepairCrew`,
а две используют `PassengerRover` и занимаются только перевозками. Так большая
очередь ремонтных работ не оставляет отряды без транспорта.

Количество экземпляров вездеходов и морских пехотинцев задаётся сценарием.
Для вездехода его начальная координата в манифесте одновременно используется как точка базирования
(условный ремонтный цех); отдельную сущность здания для этого вводить не требуется.
DSL описывает только поведение соответствующей сущности.

## Ремонт неисправностей

Повреждение объекта по-прежнему создаёт `RepairJob`. Новое правило: задание не
становится доступным в `view.active_jobs` непосредственно в момент поломки.
В `WorldConfig.repair.dispatchDelaySeconds` задаётся задержка диспетчеризации.
По умолчанию это 120 секунд.

После завершения задержки существующая логика `RepairCrew` выбирает ближайшее
задание, едет к нему и вызывает `repair.request`.

## Перевозка

Для запроса поездки используется уже существующий механизм `send`, поэтому
новый opcode VM и новый транспортный механизм брокера не нужны.

Событие языка:

```colony
event VehicleTransportRequest {
    destination: Position;
}
```

Наблюдение `available_vehicles` содержит `VehicleTarget`, у которого поле `id`
имеет тип `Ref<Rover>`. Поэтому программа может передать наблюдаемый вездеход
непосредственно в `send`:

```colony
if let vehicle = nearest(view.available_vehicles) {
    if vehicle.distance <= view.boarding_radius {
        send VehicleTransportRequest { destination: view.workplace } to vehicle.id;
    } else {
        motion.request(vehicle.position, 1.4mps);
    }
}
```

Мировое ядро самостоятельно проверяет расстояние посадки, вместимость,
поломку транспортного средства и конфликт маршрутов.

Жителю ровер виден, только если стоит в депо не дальше `transport.walkRadius`
и в нём есть место для этого жителя. Места достаются идущим к машине по
удалённости: толпа, увидевшая один ровер, за один шаг делится на тех, кто
едет, и тех, кто сразу идёт пешком. Машина с пассажирами видна только тем, чьё
место работы совпадает с её маршрутом, поэтому жители ездят только на работу.
Ровер с жителями уезжает, когда заполнен, когда к нему больше никто не идёт или
когда с первой посадки прошло `transport.boardingWaitSeconds`. Наблюдение
`boarding_pending` сообщает ремонтной бригаде, что к машине идут пассажиры, и
она не уезжает на ремонт. Физическое положение
пассажира во время поездки совпадает с положением вездехода.

Вместимость по умолчанию — пять пассажиров. `view.boarding_radius` у людей и
морпехов соответствует `transport.boardRadius`; `view.work_radius` ровера —
`repair.workRadius`. Эти значения используются непосредственно в поведении.
Скорость ровера ограничивается `repair.roverSpeed`.

Посадка сразу переносит пассажира в координаты ровера. Собственные команды
движения пассажира игнорируются до следующего после высадки шага. При поломке
машины пассажиры высаживаются в её текущей точке. Гибель последнего пассажира
освобождает маршрут; погибшие люди и морпехи не создают ремонтных заданий.

## Морские пехотинцы

Вводится тип `Marine`. В сценарии один отряд описывается пятью экземплярами с
общим параметром `squad` и одним лидером. Допускаются отряды из четырёх или пяти
живых бойцов.

Отряд начинает реагировать на присутствие ксеноморфов только после задержки
`WorldConfig.marine.responseDelaySeconds`. По умолчанию — 300 секунд с начала
сценария; начальные ксеноморфы считаются появившимися в момент `t = 0`.

После получения возможности реагировать бойцы направляются к свободному
вездеходу. Вездеход ожидает, пока все живые участники одной группы не окажутся
на борту, после чего доставляет их к выбранному ксеноморфу. Первый севший боец
закрепляет машину за отрядом: она остаётся видимой остальным членам отряда,
а другой отряд или гражданский пассажир не может занять её. Цель выбирается
по наблюдению лидера и закрепляется при первой посадке; маршрут отслеживает
её перемещение. Все бойцы получают одну цель, атака разрешается после высадки
всего отряда в пределах `marine.assaultRadius` от цели.

Если численность отряда ниже минимума, перевозка отменяется с высадкой
пассажиров. Если закреплённая цель погибла, отряд берёт ближайшую цель,
которую видит лидер, и машина едет к ней. Закрепление снимается, когда цель
погибла или весь отряд вернулся на базу. Отряд, который целиком не помещается в машину, не
начинает посадку. Неполная группа ждёт, машина не уезжает с частью бойцов.

Если колония обнесена забором, отряды выезжают только на ксеноморфов внутри
него. Отряд, собравшийся у цели, прогоняет её независимо от исхода выстрела:
у ксеноморфа появляется наблюдение `routed`, он бежит наружу через ближайший
пролом, а без пролома проламывает забор изнутри. Снаружи он держится
`marine.routSeconds` (по умолчанию 600 секунд), затем снова бродит за забором.
Прогнанный ксеноморф перестаёт быть целью отрядов.

Атаку выполняет лидер. Вероятность успеха задаётся параметром поведения и в
эталонном сценарии равна 5%:

```colony
param success_probability: Probability;

if view.squad_leader && chance(success_probability, "marine_assault") {
    damage.request(target.id, 100hp, MarineAssault);
}
```

При неудаче попытка на месте не повторяется: бойцы возвращаются к своему месту
базирования, две минуты перезаряжаются и затем готовы к следующему выезду.
Каждый боевой выезд остаётся отдельной дискретной попыткой, а колония не
остаётся без защиты после первой неудачи. Отряд без цели возвращается на базу,
а не остаётся там, где его высадили.

## VM и брокер

Новые инструкции VM не требуются. Используются уже существующие `SEND`,
`MOTION_REQUEST`, `DAMAGE_REQUEST` и `CHANCE`.

Брокер также не получает нового типа транспортного кадра: событие `SEND` уже
является частью существующего протокола и переносит произвольную полезную
нагрузку.

Изменения требуются только в World Kernel, контракте наблюдений/типов и
frontend-визуализации.

Полный конфиг и запуск: [examples/physics/full.md](../../examples/physics/full.md).
