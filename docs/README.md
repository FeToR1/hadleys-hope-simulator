# LV-426: симуляция посёлка

<img width="1461" height="828" alt="Screenshot 2026-09-20 at 16 35 59" src="https://github.com/user-attachments/assets/95fd76b1-cbce-4605-a3e6-7d548bb1309d" />

Учебный проект: симуляция шахтёрского посёлка на LV-426 примерно на 300 домов. Поведение каждой сущности
описано на собственном языке Colony, скомпилировано в стековый байт-код и исполняется отдельным процессом
операционной системы. Физические последствия считает единое ядро мира.

## Что уже работает

| Часть | Состояние |
|---|---|
| Язык Colony | Грамматика ANTLR4, AST, семантика, типы и единицы, IR |
| Компилятор | Два бэкенда: переносимый JSON-артефакт v1 и двоичный [CVM v2](cvm-v2.md) |
| Стековая ВМ | C++20 в [native/](../native), верификатор байт-кода, один процесс на сущность |
| Брокер | Отдельный процесс, барьер тика, один процесс ВМ на программируемую сущность |
| Ядро мира | Климат, электросеть, тепло, вода и замерзание, здоровье, ремонт, экономика, транспорт и отряды морской пехоты |
| Наблюдение | HTTP и SSE шлюз, управление прогоном, React-дашборд |
| Проверки | Тесты Kotlin и фронтенда, модульные тесты C++, [векторы соответствия](../conformance) |

Измерено на четырёх ядрах: 1218 процессов стартуют за 15 секунд, один модельный шаг стоит 33 мс,
снимки процессного режима совпадают с эталонным исполнителем бит в бит.

## Как запустить

Нужны JDK 17, CMake с компилятором C++20 и Node 20 или новее.

```bash
# 1. Нативная ВМ
cmake -S native -B native/build -DCMAKE_BUILD_TYPE=Release
cmake --build native/build

# 2. Компилятор и среда исполнения
./colony-dsl-parser/gradlew -p colony-dsl-parser test installDist
BIN=colony-dsl-parser/build/install/colony-dsl-parser/bin/colony-dsl-parser

# 3. Каскад аварии на настоящих процессах, снимки в файл
$BIN run-native examples/physics/cascade.json cascade.jsonl

# 4. То же с дашбордом: шлюз и, во втором терминале, интерфейс
$BIN serve-native examples/physics/cascade.json 8080
cd frontend && npm ci && npm run dev    # затем открыть адрес Vite: интерфейс подключится сам
```

На Windows вместо `./gradlew` используется `gradlew.bat`, а исполняемый файл называется
`colony-dsl-parser.bat`.

### Docker

Docker Desktop на macOS Apple Silicon автоматически выберет arm64-варианты
официальных образов. Для запуска шлюза и дашборда:

```bash
docker compose up --build
```

После сборки откройте <http://localhost:5173>. Backend доступен отдельно на
<http://localhost:8080>, а Vite проксирует к нему запросы `/health`, `/stream` и
`/control`.

При сборке Docker выполняются `installDist` для Gradle-приложения и production
сборка frontend; полный набор интеграционных тестов Gradle остаётся отдельной
проверкой проекта, так как он использует дополнительные репозиторные fixtures.

Шаг 3 (нативная симуляция в файл) запускается отдельным профилем и сохраняет
результат в `results/cascade.jsonl`:

```bash
docker compose --profile simulation run --rm simulation
```

Для остановки dashboard-режима используйте `docker compose down`.

## Куда смотреть в интерфейсе

| Вкладка или панель | Что показывает |
|---|---|
| **Графики** | Четыре величины посёлка по времени: средняя температура домов, выданная мощность, дома без воды, начислено всего. Наведение ведёт перекрестие по всем четырём сразу, кнопка «Таблица» показывает те же числа списком |
| **2D карта** | Дома, жители, ксеноморфы, вездеходы, морские пехотинцы и узлы сети; цвет — состояние, красный значит сломан |
| **Топология сетей** | Подстанция, столбы, насос и трубы со связями: видно, какие дома остались за сломанным столбом |
| Логика каскада событий | Цепочка причин последней поломки, по ссылкам `causationId` настоящих событий |
| Расходы | Итог, разбивка по электричеству, воде и ремонту, и кто платит больше |
| Журнал событий | Что установил мир: атаки, поломки, потеря и возврат питания и воды, ремонты |
| Инспектор сущности | Метрики, PID процесса и личное состояние ВМ выбранного объекта |

Кнопки управления прогоном (пауза, один шаг, заново, скорость) находятся в правом верхнем углу. Кнопка «Экспорт отчёта в CSV» выгружает метрики текущего снимка.
Полная история прогона остаётся в файле `run-native SCENARIO OUT.jsonl`: одна строка на шаг,
со всеми сущностями, событиями и проводками, для внешних графиков.

Прочие команды: `check` разбирает один файл, `emit` собирает `.cvm`, `disasm` печатает байт-код,
`contract` выводит контракт, `conformance` пересоздаёт векторы, `prepare` разворачивает манифест,
`run` и `serve` делают то же в одном процессе без нативных ВМ.

## Демонстрационный каскад

По умолчанию Docker запускает большой сценарий `examples/physics/full.json` с 300 домами. Компактный
`examples/physics/cascade.json` воспроизводит базовую цепочку аварии и одновременно содержит один вездеход и
отряд из пяти морских пехотинцев. Задержка диспетчеризации ремонта — 120 с, задержка выезда пехоты — 300 с;
вероятность успешной атаки отряда — 5%. Ремонт и перевозка делят общий парк, поэтому
время событий зависит от занятости ровера. Основная цепочка:

```text
ксеноморф разрушает распределительный столб → дома теряют питание
дома остывают → трубы замерзают → дома теряют воду
после задержки диспетчеризации ровер едет к поломке и ремонтирует её
восстанавливаются сети; расходы начисляются с интервалом из конфига
```

Для масштаба есть `examples/physics/colony-300.json`: 300 домов, 6 бригад, 12 ксеноморфов и один отряд из 5 морских пехотинцев — всего 1223 процесса.

Полный сценарий со всеми параметрами мира: [`examples/physics/full.json`](../examples/physics/full.json) —
300 домов, 6 роверов, 2 отряда, 12 ксеноморфов, модельные сутки.
[Состав, параметры и команды запуска](../examples/physics/full.md). В Docker сценарий выбирается
переменной `HH_SCENARIO`; без неё используется `full.json`. Для компактного запуска укажите
`HH_SCENARIO=examples/physics/cascade.json`.

## Границы текущей версии

Реализованы обязательные примеры поведения (отключение отопления без людей, вероятностный вандализм,
движение и атаки ксеноморфа, ремонт бригадой, задержанная диспетчеризация ремонта, перевозка пассажиров
вездеходом и выезд отряда морской пехоты). Реактор, солнечная станция, ИБП и насос пока объекты мира,
а не отдельные ВМ: их режимы не программируются на Colony. Канализация, мусор и дополнительные
инфраструктурные сущности остаются следующими итерациями. Черновики синтаксиса для ещё не реализованных
видов лежат в [examples/drafts](../colony-dsl-parser/examples/drafts).
