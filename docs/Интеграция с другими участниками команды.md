## 1. Участнику №2 (Брокер, Запуск процессов и Интеграция)
Этот человек — ваш главный союзник. От него зависит, как данные пойдут на фронтенд. Передайте ему следующие пункты:

* Протокол обмена: «Мы делаем UI на React и PixiJS v8. Для получения пакетов данных используем SSE (Server-Sent Events), если фронтенд работает в режиме "только чтение". Если планируем управлять симуляцией (пауза/старт) — берем WebSockets. Нам нужен один эндпоинт, который стримит тики».
* Батчинг (Пакетная передача): «Не присылай сообщения от каждой ВМ отдельно! Фронтенд ждет единый пакет TickBatch строго раз в 100–500 мс по окончании обсчета физического тика в World Kernel».
* Идентификаторы (ID) сущностей: «У каждого дома, прибора (чайник, обогреватель), жителя и ксеноморфа должен быть строковый уникальный id (например, house_114, heater_114, xeno_3), который сохраняется между тиками. Фронтенд будет искать объекты в памяти по этим ID».
* Привязка к PID: «Внутри данных каждого прибора или дома обязательно передавай pid реального процесса ОС. Мы будем выводить его в Sidebar, чтобы на защите препод показать: вот этот квадрат на карте — это живой процесс в диспетчере задач».

## 2. Участнику №7 (Физика, Ресурсы и Экономика) / Координатор
Этот человек наполняет пакет данными о состоянии мира.

* Координатная сетка: «Для карты на PixiJS нам нужны координаты объектов. Договоримся о сетке. Например, карта поселка — это матрица 100х100 или абсолютные координаты в метрах. Каждый дом должен иметь фиксированные x и y. Агенты (жители и ксеноморфы) при перемещении должны присылать новые x и y на каждом тике».
* Статусная модель для каскада аварий: «Чтобы мы могли красиво подсветить на карте твой сценарий “отключение сети -> замерзание труб -> расходы”, нам нужно поле status со значениями nominal (ок), warning (внимание), critical (авария), dead (разрушено/обесточено). Фронтенд на PixiJS будет мгновенно перекрашивать дома на основе этого поля».
* Связи для графа сетей (AntV G6): «Для визуализации сетей электричества и водоснабжения нам нужен граф. Присылай для каждого узла массив connectedTo: [id1, id2], чтобы мы знали, как нарисовать трубы и провода от реактора к домам».

## 📑 Шаблон сообщения для отправки в чат команды:

Привет, команда! По фронтенд-части симуляции LV-426 мы зафиксировали следующий стек: Node.js v24.14.0, React, PixiJS v8 (для 2D-карты поселка на GPU) и AntV G6 (для графов электросетей и KPN-связей процессов).
Чтобы интерфейс стабильно держал 60 FPS при обсчете 1300+ процессов ВМ и не вешал компы, нам нужно утвердить единый JSON-контракт для обмена данными через Брокер (WS/SSE). Координатор должен отдавать данные батчами (пакетами) раз в 100–500 мс по окончании модельного тика.
Вот базовый интерфейс одного объекта в пакете, под который нужно подстроиться при сборке данных на бэкенде:

interface EntityState {
  id: string;        // Уникальный ID (house_1, xeno_12)
  pid: number;       // Реальный PID процесса ОС этой ВМ
  type: 'house' | 'heater' | 'kettle' | 'civilian' | 'xenomorph' | 'power_node';
  status: 'nominal' | 'warning' | 'critical' | 'dead'; // Для перекраски на карте
  metrics: { temperature?: number; power_consumption?: number; stress?: number; };
  connectedTo: string[]; // ID узлов, куда ведут провода/трубы от этого объекта
  coordinates: { x: number; y: number }; // Позиция на карте
}

Давайте на ближайшем созвоне зафиксируем координатную сетку (размеры карты) и утвердим, как ВМ будут прокидывать свои текстовые логи через Координатор на фронтенд.
