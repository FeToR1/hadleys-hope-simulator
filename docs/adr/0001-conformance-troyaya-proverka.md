# 0001. Кросс-проверка исполнителей по conformance-векторам

- **Статус:** принято (ретроспективно зафиксировано; реализовано в коммитах 7749397, dfd93b2 от 2026-09-22)
- **Дата:** 2026-09-22

## Контекст

Семантика исполнения должна быть идентичной у эталонной JVM-ВМ (`ReferenceVm`) и нативной C++ `hh-vm`:
расхождение делает нативный режим бесполезным и ломает детерминизм приёмо-сдаточных критериев
(«повтор с теми же входами совпадает», [requirements.md](../requirements.md)). Нужен независимый арбитр,
а не взаимное доверие двух реализаций.

## Решение

- Векторы `conformance/*.json` (heater, kettle, resident, xenomorph, language, prng) генерируются командой
  CLI `conformance`: программа + начальное состояние + кадры + ожидаемые намерения/события/состояние.
- Одна и та же программа прогоняется тремя исполнителями: Kotlin (`ConformanceVectorsTest`),
  C++ (`NativeConformanceTest` через реальные процессы hh-vm) и независимый Python-ВМ
  (`conformance/run_vectors.py`), написанный по текстовой документации.
- Сравнение: числа по значению, порядок списков важен; ошибочный шаг обязан сохранить прежнее состояние и счётчики.
- Задокументировано в [architecture.md](../architecture.md) (диаграмма 2.3); проверяемые гарантии — [spec/runtime-tick.md](../spec/runtime-tick.md).

## Альтернативы

- Только юнит-тесты каждой ВМ по отдельности — не ловят расхождений между ними.
- Сверка полных прогонов сценариев — слишком крупнозернистая и медленная для локализации отличий.

## Последствия

- Любое изменение семантики требует обновления векторов; устаревшие векторы тест обнаруживает
  и подсказывает команду перегенерации.
- Python-ВМ — третья реализация, которую надо поддерживать при изменении набора команд;
  плата за независимый арбитр.
- PRNG тоже зафиксирован векторами (`prng.json`), что позволяет разным языкам давать одинаковые случайные потоки.
