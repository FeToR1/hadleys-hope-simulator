# Архитектурные решения (ADR)

> **Статус:** актуально · **Обновлять при:** изменении самого процесса ADR

## Что такое ADR

ADR (Architecture Decision Record) — короткий документ, фиксирующий одно архитектурное решение:
контекст проблемы, выбранное решение, рассмотренные альтернативы и последствия.

## Когда ADR обязателен

Пиши ADR до реализации, если решение:

- меняет структуру компонентов, их границы или потоки данных;
- меняет форматы, протоколы или контракты (`.cvm`, INIT/FRAME/RESULT, HTTP/SSE, contract.json, сценарии);
- меняет стек или ключевые зависимости (Kotlin/ANTLR4, C++20, React/Pixi/Three, Gradle);
- заметно меняет производительность или детерминизм (пулы потоков, кэши, форматы кодирования);
- отменяет или заменяет ранее принятое решение.

ADR **не нужен** для: исправлений багов без смены подхода, добавления сущностей по готовому
конвейеру расширения ([architecture.md](../architecture.md)), обновления документации.

## Процесс

1. Скопируй [_template.md](_template.md) в `NNNN-короткое-имя.md` (NNNN — следующий номер по порядку).
2. Заполни разделы; статус нового ADR — «предложено», после слияния — «принято».
3. Отмена/замена решения: новый ADR со статусом, ссылающийся на старый; старый помечается «заменён ADR-NNNN» (сам текст не редактируется).
4. Изменение затронутых спек ([spec/](../spec/)) — в том же коммите, что и ADR.
5. Факт изменения — запись в [CHANGELOG](../../CHANGELOG.md).
