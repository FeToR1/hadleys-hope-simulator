# ADR 0010: единственный исполнитель CVM2 и настройки на Colony

> **Статус:** принято · **Аудитория:** разработчики · **Обновлять при:** изменении компиляции и подготовки запусков · **Источник истины:** Colony.g4, colony.compiler, colony.cvm, colony.runtime

## Контекст

Два исполняемых артефакта и JVM-интерпретатор дублируют уже работающий C++ исполнитель.
JSON-конфигурация запуска не использует выражения и типизированные литералы Colony.
Пользователь требует убрать первую ВМ и расширить существующий язык для настройки запусков.

## Решение

Оставить один backend компилятора: IR → CVM2. Удалить JSON-байт-код v1 и `ReferenceVm`.
Метаданные типов параметров и наблюдений остаются в компиляторе для привязки сценария,
но не являются второй исполняемой программой. Все режимы исполнения используют `hh-vm`.
Регрессионные векторы хранят бинарный артефакт и ожидаемые результаты; проверка больше
не называется сравнением независимых ВМ. Полезные семантические тесты запускают C++.

Добавить отдельное правило входа `.settings` в `Colony.g4`. Использовать общие выражения,
AST литералов и вычисление констант. Настройки задают исходники, шаблоны поведения,
параметры, группы экземпляров и конфигурацию мира. Вид объекта выводится из поведения;
значения параметров проверяются против его объявлений. Настройки не содержат байт-код.
Существующие JSON-сценарии остаются входом совместимости для тестов и готовых примеров.

## Альтернативы

Скрыть v1 за новым названием: сохраняет два интерпретатора и не выполняет требование.
Добавить TOML/YAML: удобнее JSON, но не расширяет Colony и дублирует синтаксис литералов.

## Последствия

Для выполнения нужен собранный `hh-vm`; JVM отвечает за компиляцию и физику мира.
Команды `compile` и `emit` создают CVM2; `prepare` больше не создаёт JSON-байт-код.
JVM-оптимизации интерпретатора удаляются вместе с ним. Conformance становится
регрессионной проверкой одного исполнителя; независимая проверка PRNG сохраняется.
Изменение синтаксиса обновляет контракт и предметную спецификацию.
