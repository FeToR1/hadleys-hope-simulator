# 0003. Пространственный хеш-индекс и кэш связей инфраструктуры

- **Статус:** принято (реализовано в de927a4, 2026-10-02; замеры в [history/optimization-5000.md](../history/optimization-5000.md))
- **Дата:** 2026-10-02

## Контекст

На 5000 домах (20 028 контекстов) проверки близости, видимости и коллизий были O(N²):
шаг без JSON занимал 7156 мс, инициализация 3820 мс (0,138 тика/с). Полный обход города
для каждой трубы/опоры в каждом снимке делал масштабирование невозможным.

## Решение

- `SpatialIndex` — 2D ячеистый пространственный хеш для неподвижных приборов: запрос соседей
  `queryRadius` за O(1); житель проверяет соседние ячейки, затем прежние условия расстояния и исправности.
- Связи потребителей с инфраструктурой рассчитываются один раз, а не в каждом снимке.
- Порядок выбора целей сохранён `(distance, id)` — предметная модель не изменилась.

## Альтернативы

- k-d дерево / R-дерево — сложнее в инкрементальном обновлении при каждом тике; сетка проще для статичных объектов.
- Оставить полный перебор — исключено целевой нагрузкой.

## Последствия

- Шаг: 7156 → 466 мс, инициализация 3820 → 380 мс (~13× суммарно в коротком сравнении, один поток).
- Точность индекса покрыта тестами: границы ячеек, отрицательные координаты, повреждённые записи.
- Правило для новых механик: любые проверки радиуса — через `spatialIndex.queryRadius(...)`, а не перебор списков
  (конвейер расширения в [architecture.md](../architecture.md)).
