# 0002. Процессная модель нативной ВМ и путь к общему исполнителю

- **Статус:** принято (общий пул исполнителей реализован 04–05.10.2026 — batch-протокол и `HH_NATIVE_WORKERS`, коммиты c795622–a4b706c)
- **Дата:** 2026-09-22 (исходное решение); целевая модель — по ТЗ от 2026-10-02

## Контекст

Исходно `hh-vm` строился по модели «одна сущность — один процесс»: маленький статический бинарник,
изолированные сбои, простая модель памяти. Целевая нагрузка — 20 028 контекстов поведения
([requirements.md](../requirements.md)); процесс на каждую сущность для неё отменён: слишком много процессов
и дорогой обмен. Текущий протокол INIT/FRAME/RESULT обслуживает ровно один контекст и без изменений
не позволяет адресовать множество контекстов.

## Решение

- Сейчас: `run-native`/`serve-native` запускают отдельный процесс hh-vm на сущность через брокер
  (`ProcessFleet`/`NativeBroker`); транспорт — stdio или TCP с двоичным кадрированием ([spec/cvm-format.md](../spec/cvm-format.md), раздел 8).
- Целевой путь (реализован в c795622–a4b706c): один общий C++ процесс — загруженный единожды байт-код, таблица
  независимых контекстов (переменные, таймеры, PRNG — в контексте), бинарные пакеты наблюдений/результатов;
  начальный диапазон 256–1024 контекста на пакет, затем подобрать по времени и памяти.
- Дальше: пул 2–4 общих исполнителей с закреплёнными контекстами, барьером тика и одним владельцем мира.

## Альтернативы

- Общая JVM (текущий `run`/`serve`) — уже работает и служит базой сверки, но JSON и объекты JVM дороги на 20k контекстов.
- Несколько потоков в одном C++ процессе — `Program::strings` мутирует при интернировании и не допускает
  наивного шаринга между потоками; потребовались бы таблица строк на поток или неизменяемый формат ID.

## Последствия

- Протокол `BATCH_INIT/BATCH_FRAME/BATCH_RESULT` реализован параллельно одиночному `INIT/FRAME/RESULT`
  (спека — [cvm-format.md](../spec/cvm-format.md), разделы 8–9); обмен JVM-координатора с брокером — двоичный `BrokerWire`.
- Ошибка контекста/исполнителя останавливает прогон без фиксации частичного тика — независимо от числа исполнителей.
