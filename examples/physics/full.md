# Полный сценарий колонии

[`full.json`](full.json) задаёт все сериализуемые параметры `WorldConfig` явно,
включая значения по умолчанию. Каталог сущностей — [`catalog.json`](catalog.json),
программы поведения — [`settlement.colony`](settlement.colony).

| Состав | Количество |
|---|---:|
| Дома | 300 |
| Обогреватели | 300 |
| Чайники | 300 |
| Жители с распорядком дня | 300 |
| Роверы: ремонт и перевозка | 4 |
| Роверы только для перевозки | 2 |
| Морпехи | 10, два отряда по пять |
| Ксеноморфы | 12 |

Всего 1228 программируемых сущностей. Реактор, солнечная станция, ИБП, насос,
распределительные столбы, трубы и секции забора создаются ядром автоматически. В нативном
режиме каждой программируемой сущности соответствует отдельный процесс ВМ.

Шаг — 1 секунда, длительность — 86400 шагов (модельные сутки), seed — 426.
Распорядок жителей начинается в 08:00; климат использует собственное время от
нуля, поэтому солнце появляется через шесть модельных часов. Сценарий включает
суточные смены, отопление, водоснабжение, замерзание труб, расходы, атаки,
ремонт и перевозку. Дальность наблюдения морпехов увеличена до 2000 м, чтобы
отряды обнаруживали цели на большой карте; ксеноморфы видят на 150 м, поэтому
расходятся по территории, а не сбегаются к одной цели.

Колонию окружает забор из секций по 60 м в 40 м от крайних объектов, включая
шахту. Ксеноморфы появляются снаружи и случайно бродят в полосе до 120 м за
забором, каждый своим путём.
Заметив людей вне дома или столб, ксеноморф идёт к цели. Упёршись в целую
секцию, он ломает её (400 hp) и проходит в пролом. Сломанная секция становится
заданием для ремонтных роверов. После укуса ксеноморф пять минут не трогает
людей, раненый житель успевает уйти домой, а дома и в ровере люди недоступны.

Житель едет на работу ровером, если свободная машина стоит в депо не дальше
120 м от него. Места достаются ближайшим из тех, кто пошёл к машине. Остальные
сразу идут пешком. Ровер ждёт всех, кому досталось место, но не дольше 90 с.
Морпехи выезжают только на ксеноморфов внутри забора. Собравшись у цели,
отряд прогоняет её: ксеноморф бежит через пролом и 10 минут держится снаружи,
а лидер отряда может его убить (5%). После атаки отряд пешком возвращается на
базу, две минуты перезаряжается и снова готов к выезду. Если цель погибла или
прогнана другим отрядом, отряд берёт ближайшую другую. Две машины с поведением `PassengerRover`
не принимают ремонтные задания: перевозка доступна и при большой очереди поломок.
Порядок популяций ставит роверы и казармы рядом; изменение порядка меняет
размещение объектов.

## Запуск

Из корня репозитория после сборки `native/` и `installDist`:

```powershell
& .\colony-dsl-parser\build\install\colony-dsl-parser\bin\colony-dsl-parser.bat serve-native examples/physics/full.json 8080
```

В другом терминале: `cd frontend`, `npm ci`, `npm run dev`; интерфейс
подключится к шлюзу сам. Для эталонного выполнения без отдельных процессов использовать
`serve` вместо `serve-native`.

Docker, PowerShell:

```powershell
$env:HH_SCENARIO = 'examples/physics/full.json'
docker compose up --build
```

Docker, bash:

```bash
HH_SCENARIO=examples/physics/full.json docker compose up --build
```

Для записи снимков использовать `run-native` вместо `serve-native` и путь
выходного JSONL вместо порта. В Docker путь сценария выбирается через
`HH_SCENARIO`, имя файла в `results/` — через `HH_OUTPUT`:

```bash
HH_SCENARIO=examples/physics/full.json HH_OUTPUT=full.jsonl docker compose --profile simulation run --rm simulation
```

Полные снимки большой колонии за сутки занимают много места. Для короткого
прогона уменьшить `ticks`, например до 1800; для компактного примера использовать
[`cascade.json`](cascade.json).

## Настройки

Все расстояния заданы в метрах, скорости в м/с, время в секундах, мощность в
ваттах, энергия в джоулях, температура в °C, деньги в минимальных денежных единицах.

| Раздел | Что задаёт |
|---|---|
| `climate` | Температура, сутки, восход, закат, облачность |
| `power` | Реактор, солнечная станция, ИБП, число домов на столб, приоритеты нагрузки |
| `water` | Мощность насоса, расход воды, порог замерзания |
| `house` | Теплопотери, теплоёмкость, отопление, параметры чайника |
| `human` | Начало распорядка дня, вред от холода, радиус вандализма |
| `marine` | Задержка выезда, радиус сбора для атаки, размеры отряда, сколько прогнанный ксеноморф держится снаружи |
| `transport` | Радиус посадки, вместимость ровера, дальность пешего подхода жителя, ожидание попутчиков |
| `repair` | Задержка заявки, время и стоимость ремонта, скорость и рабочий радиус ровера |
| `tariffs` | Тарифы и интервалы начислений |
| `sight` | Дальность наблюдения морпехов и ксеноморфов, ограничение списков целей |
| `fence` | Забор: включён ли, отступ, длина и прочность секции, полоса обхода ксеноморфов снаружи |

Мощность обогревателя и вероятность успеха атаки отряда задаются в каталоге:
`household.objects.heater.params.rating` и
`marine_squad.objects.marine1.params.success_probability` (лидер, по умолчанию 0.05).
Одна попытка атаки за выезд, затем возвращение к месту базирования и новая
готовность через две минуты. Ровер ждёт полный отряд и отслеживает перемещение цели. После высадки `RepairCrew`
возвращается к ремонту, `PassengerRover` — в депо за следующими пассажирами.

Полнота относится к текущей реализации: канализация и вывоз мусора пока не
реализованы. `repair.materials` сейчас является справочным запасом; расход и
пополнение материалов ещё не моделируются. `sight.attackRadius` сохранён как
параметр мира, но дистанцию атаки ксеноморфа задаёт программа `settlement.colony`.
